## 启动 Job {#launching-a-job}
`harbor run --launch` 命令会尝试在你的个人组织下启动 Job（任务运行集合）。

`--launch` 标志可以与单个 Agent/模型组合一起使用（例如 `harbor run --launch -a claude-code -m anthropic/fable-5 -d harbor/hello-world`）。
Agent/模型组合扫描必须通过配置文件启动（例如 `harbor run --launch -c config.yaml`）。

```yaml
# config.yaml
job_name: opus-vs-codex-sweep
organization: my-org          # omit to use your personal org
credential_mode: gateway      # or "direct"

n_attempts: 3                 # 1-10
n_concurrent_trials: 32       # 1-1000

# Every agent runs against every task. Trials = n_attempts x tasks x agents.
agents:
  - name: claude-code
    model_name: anthropic/claude-opus-4-1
    secrets:
      - name: ANTHROPIC_API_KEY
        tag: default
        as: ANTHROPIC_API_KEY

  - name: claude-code
    model_name: anthropic/claude-sonnet-5-5
    secrets:
      - name: ANTHROPIC_API_KEY
        tag: default
        as: ANTHROPIC_API_KEY

  - name: codex
    model_name: openai/gpt-5
    secrets:
      - name: OPENAI_API_KEY
        tag: default
        as: OPENAI_API_KEY
      - name: HF_TOKEN
        tag: default
        as: HF_TOKEN
    n_concurrent: 8           # per-agent sub-limit under n_concurrent_trials
    env:
      RUST_LOG: info          # nonsensitive only - secrets go in `secrets`

  - name: oracle              # needs no inference credential
    secrets: []

datasets:
  - name: terminal-bench/terminal-bench-2-1
    ref: "6"                  # `ref` or `version`, never both
    n_tasks: 25
    exclude_task_names:
      - "flaky-*"

tasks:
  - name: harbor/hello-world
    ref: latest

# Supplied for this job only, read from your local environment at launch.
job_secrets:
  HF_TOKEN:
    from_env: HF_TOKEN

retry:
  max_retries: 2
  include_exceptions:
    - EnvironmentStartError
```

### 注入密钥 {#injecting-secrets}

使用 `--stored-secret NAME[@TAG][=AS]` 选择已存储的凭据，或使用
`--one-off-secret NAME` 从本地环境读取仅用于当前 Job 的密钥。
这些标志会将密钥选择添加到 Job 中的每个 Agent（智能体）。若要按 Agent 单独选择，
请在配置中使用 `agents[].secrets`。

```bash
harbor run --launch -d harbor/hello-world -a codex -m openai/gpt-5 \
  --stored-secret OPENAI_API_KEY@production=MODEL_KEY --api-key-name MODEL_KEY
```

有关标签、
别名和一次性密钥的优先级，请参阅[Agent 密钥](/hosted-harbor/submitting-jobs#agent-secrets)。

| 标志 | 值 | 作用 |
| --- | --- | --- |
| `--dry-run` | — | 不将 Job 加入队列，仅验证配置。解析 Task（任务）、Agent 和所属组织，检查密钥选择并报告 Trial 数量。 |
| `--org` | `TEXT` | 托管 Job 的所属组织。默认使用你的个人组织。 |
| `--credential-mode` | `gateway` \| `direct` | `gateway` 通过 Hub 代理密钥；`direct` 将真实密钥交给 Agent。 |
| `--stored-secret` | `NAME[@TAG][=AS]` | 选择所属组织中已存储的密钥。可重复指定。 |
| `--one-off-secret` | `NAME[=VALUE]` | 仅为当前 Job 提供密钥。裸名称 `NAME` 会从环境变量读取。可重复指定。 |
| `--env-file` | `PATH` | 加载 `.env` 文件。文件中的每个名称都会被选中，效果与 `--one-off-secret` 相同。 |
| `--registry-secret` | `HOST=NAME_OR_ID` | 为私有镜像主机固定一个已存储的拉取密钥。可重复指定。 |
| `--no-secrets` | — | 启动时不提供任何凭据。 |

`--launch` 和 `--upload` 不能同时使用，因此上传标志不适用于
托管启动：`--upload`、`--public` / `--private` 和 `--share`。

### 凭据代理配置 {#credential-proxy-configuration}

使用 `environment.credential_proxy` 在托管 Job 配置中描述目标规则和 HTTP（超文本传输协议） 标头
模板。

以下示例为发往 `inference.example.com` 且路径以
`/v1/` 开头的 `POST` 请求定义一条规则。该规则引用 `NEW_LLM_API_KEY`，必须在 Agent 的 `secrets`
列表中选中该密钥。有关已存储密钥和一次性凭据选项，请参阅[注入密钥](#injecting-secrets)。


```yaml config.yaml
credential_mode: gateway
agents:
  - name: codex
    model_name: openai/gpt-5
    secrets:
      - name: OPENAI_API_KEY
        tag: default
        as: OPENAI_API_KEY
      - name: NEW_LLM_API_KEY
        tag: default
        as: NEW_LLM_API_KEY
tasks:
  - name: harbor/hello-world
    ref: latest
environment:
  credential_proxy:
    inference.example.com:
      - match:
          path:
            startsWith: /v1/
          method: [POST]
        transform:
          - headers:
              Authorization: "Bearer ${NEW_LLM_API_KEY}"
```

每个目标都是一个精确 DNS 主机，并映射到一组规则：

| 字段 | 说明 |
| --- | --- |
| `match.path.startsWith` | 可选的路径前缀匹配条件，例如 `/v1/`。 |
| `match.method` | 可选的 HTTP 方法列表，例如 `[POST]`。 |
| `transform` | 必需的标头转换列表。每项包含一个 `headers` 映射，将标头名称映射到字符串模板。 |

省略 `match` 表示匹配发往该主机的所有请求。代理规则不会授予
网络访问权限；网络允许列表需单独配置。

#### 标头模板 {#header-templates}

标头值可以将字面文本与 `${SECRET_NAME}` 引用组合使用，
同一个值中也可以包含多个引用。密钥名称必须以大写字母开头，
且只能包含大写字母、数字或下划线，长度最多为 64 个字符。
CLI 会在内存中保留模板，绝不会将本地环境变量的
值替换进模板。

## 重新评分 {#regrading}

添加 `--launch` 可使用更新后的 Verifier（验证器） 对 Hub 中已记录的结果重新评分。此操作
会创建新的私有 Job，不会重新运行 Agent，也不会更改来源数据。

使用 `--org` 指定此次启动所使用的组织额度、权限和
凭据。它必须与来源组织一致，而且你必须拥有在该组织中启动 Job 的权限；仅有共享读取权限并不足够。


### 重新评分整个 Job {#regrade-a-job}

```bash
harbor job regrade <job-uuid> --launch --org <org> -d org/dataset@version
harbor job regrade <job-uuid> --launch --org <org> -p ./updated-tasks
```

使用 `-d` 指定数据集，使用 `-p` 指定本地 Task 目录，或使用 `-t` 指定注册表 Task。
这些选项可以重复指定并组合使用。Verifier 会按 Task 名称匹配。
Harbor 会选择带有已记录归档的最新 Trial 尝试。

### 重新评分单个 Trial {#regrade-a-trial}

```bash
harbor trial regrade <trial-uuid> --launch --org <org> -t org/task@ref
```

`-t` 和 `-p` 必须且只能指定一个；使用 `-p` 时，请提供单个 Task 目录。
本地 Verifier Task 会作为临时私有 Package 上传。添加 `--yes`
即可在无需提示的情况下确认启动和上传。

### 要求 {#requirements}

托管重新评分目前支持带独立 Verifier 的单步骤 Trial。
来源 Trial 必须已完成，替换 Task 必须具有相同名称，
并且能够根据已记录的工件评分。来源必须是 Hub UUID。

使用 `--dry-run` 可在不创建 Job 的情况下验证配置。对于本地 Verifier Task，
该命令会检查输入但不上传；完整的来源校验会在启动时进行。

### 选项 {#options}

以下选项配合 `--launch` 使用。凭据详情请参阅
[密钥选项](#injecting-secrets)。

| 选项 | 说明 |
| --- | --- |
| `--launch` | 在 Hosted Harbor（Harbor 托管服务） 上运行重新评分。 |
| `--org NAME` | 启动组织。必填，且必须与来源组织一致。 |
| `-p, --task-path PATH` | 本地 Verifier Task。Job 操作也接受父目录；Job 操作中可重复指定。 |
| `-t, --task REF` | 注册表中的 Verifier Task，例如 `org/task@ref`。Job 操作中可重复指定。 |
| `-d, --dataset REF` | 包含 Verifier Task 的数据集。仅适用于 Job 重新评分；可重复指定。 |
| `-n, --n-concurrent N` | 并发重新评分数量。仅适用于 Job 重新评分。 |
| `--job-name NAME` | 新托管 Job 的名称。仅适用于 Job 重新评分。 |
| `--trial-name NAME` | 当前用于设置 Trial 重新评分所创建的新托管 Job 名称。 |
| `--ve, --verifier-env KEY=VALUE` | Verifier 环境变量。可重复指定。 |
| `--stored-secret NAME` | 来自启动组织的已存储 Verifier 凭据。可重复指定。 |
| `--one-off-secret NAME[=VALUE]` | 仅用于该 Job 的凭据；裸名称 `NAME` 会从本地环境读取。可重复指定。 |
| `--registry-secret HOST=NAME_OR_ID` | 选择用于拉取私有镜像的已存储凭据。可重复指定。 |
| `--use-static-ip` | 使用静态出站 IP。否则服务器会选择默认值。 |
| `-y, --yes` | 无需提示即可确认启动及本地 Task 上传。 |
| `--dry-run` | 在不创建 Job 的情况下验证配置。 |

## 列出 Job {#listing-jobs}
运行 `harbor hub job list` 可列出 Hub 上当前用户有权查看的所有 Job。

| 标志 | 值 | 作用 |
| --- | --- | --- |
| `--scope` | `my` \| `shared` \| `all` | 可见范围。默认值 `my` 表示仅查看自己拥有的 Job。 |
| `--search` | `TEXT` | 仅列出名称包含该子字符串的 Job。 |
| `--agent` | `NAME` | 按 Agent 名称筛选。可重复指定；多个值按任意匹配处理。 |
| `--provider` | `NAME` | 按模型提供方筛选。可重复指定。 |
| `--model` | `NAME` | 按模型筛选。可重复指定。 |

## Job 概览 {#job-overview}
运行 `harbor hub job show JOB_ID JOB_ID_2 ...` 可查看 Job 概览，内容类似 Hub 上显示的信息。

概览会显示 Trial、错误和重试的数量，各项
指标的平均回报、美元成本和 Token 用量。

## 按 Task 查看 Job 明细 {#per-task-job-breakdown}
运行 `harbor hub job tasks JOB_ID` 可查看 Job 按 Task 划分的明细。

| 标志 | 值 | 作用 |
| --- | --- | --- |
| `--search` | `TEXT` | 仅列出名称包含该子字符串的 Task。 |
| `--agent`、`--provider`、`--model` | `NAME` | 用法与 [`job list`](#listing-jobs) 相同。 |

## Trial 概览 {#trials-overview}
运行 `harbor hub job trials JOB_ID JOB_ID_2 ...` 可列出一个或多个 Job 中的 Trial。
在交互式终端中，你可以切换页面审查所有 Trial，无需再次运行命令。

| 标志 | 值 | 作用 |
| --- | --- | --- |
| `--search` | `TEXT` | 仅列出名称包含该子字符串的 Trial。 |
| `--agent`、`--provider`、`--model` | `NAME` | 用法与 [`job list`](#listing-jobs) 相同。 |
| `--limit` | `N` | 页面大小。此处默认值为 100。 |
| `--failed-only` | — | 仅列出发生错误或失败的 Trial。 |
| `--include-retries` | — | 包含重试历史记录，而非仅显示最近一次执行。 |
| `--sort-by` | `started_at` \| `task_name` \| `name` \| `error_type` | 排序列 |
| `--sort-order` | `asc` \| `desc` | 排序方向 |

## 比较多个 Job {#comparing-2-or-more-jobs}
运行 `harbor hub job compare JOB_ID JOB_ID_2 ...` 可并排比较各 Job 在不同 Task 上的表现。

## Job 可见性 {#job-visibility}
运行 `harbor hub job shares JOB_ID` 可查看 Job 分享给了谁。结果包括组织和用户。

## 重命名 Job {#renaming-jobs}
运行 `harbor hub job rename JOB_ID "NEW NAME"` 可更改 Hub 上显示的名称。
这不会更改 Job ID、工件身份标识或已提交的
配置。添加 `--json` 可打印重命名 RPC 响应。

## 转移 Job 所有权 {#transferring-job-ownership}
运行 `harbor hub job transfer JOB_ID ORGANIZATION` 可将已完成的 Job
及其所有 Trial 转移到你拥有的另一个组织。Job 和 Trial ID 不会
更改。目标组织必须已能访问 Job 所依赖的所有执行资源。
used by the job.

命令会提示确认；编写脚本时请传入 `--yes` / `-y`。默认情况下，
来源组织仍保留共享读取权限，且会永久移除该 Job 专用的
密钥。传入 `--drop-source-access` 可移除来源组织的授权，或传入
`--keep-job-credentials` 保留并重新授权你最初提供的密钥。
originally supplied.

## 删除 Job {#deleting-jobs}
运行 `harbor hub job delete JOB_ID JOB_ID_2 ...` 可从 Hub 永久删除自己拥有的 Job，以及其所有 Trial 和分享关系。

删除前会提示确认；传入 `--yes` / `-y` 可跳过提示（编写脚本或通过管道执行时必须传入）。

只有 Job 所有者可以删除 Job。已关联排行榜提交的 Job 和仍在运行的托管 Job 不能删除。

## 托管 Job 状态 {#hosted-job-status}
运行 `harbor hub job status JOB_ID` 可查看 Job 状态，包括等待中、运行中、失败和已完成 Trial 的数量。

## 查看 Trial {#trial-show}
运行 `harbor hub trial show TRIAL_ID` 可查看单个 Trial 的元数据。

## 下载 Trial {#downloading-a-trial}
运行 `harbor hub trial download TRIAL_ID` 可下载指定 Trial。

| 标志 | 值 | 作用 |
| --- | --- | --- |
| `--output-dir`、`-o` | `PATH` | 保存 Trial 文件的目录。默认值为 `./trials`。 |
| `--overwrite` | — | 替换现有 Trial 目录。 |
| `--trajectory` | — | 仅下载 `trajectory.json`。如果该 Trial 没有存储轨迹，则报错。 |

## 重试托管 Trial {#retrying-a-hosted-trial}
对于远程启动的 Job 中的 Trial，可以运行 `harbor hub trial retry TRIAL_ID` 进行重试。

这些标志会累积为筛选条件。`harbor hub trial retry --job JOB_ID --failed-only`
会先选择 Job 中的所有 Trial，再筛选出失败项。

| 标志 | 值 | 选择范围 |
| --- | --- | --- |
| `--job` | `JOB_ID` | 该 Job 中的所有 Trial。 |
| `--search` | `TEXT` | 名称包含该子字符串的 Trial。 |
| `--agent` | `TEXT` | 使用该 Agent 运行的 Trial。 |
| `--provider` | `TEXT` | 使用该提供方运行的 Trial。 |
| `--model` | `TEXT` | 使用该模型运行的 Trial。 |
| `--task` | `TEXT` | 针对该 Task 运行的 Trial。 |
| `--exception` | `TEXT` | 因该异常失败的 Trial。 |
| `--failed-only` | — | 仅选择失败的 Trial。 |
| `--yes` | — | 跳过确认。 |

## 取消托管 Trial {#canceling-a-hosted-trial}
取消托管 Trial 时，运行 `harbor hub trial cancel TRIAL_ID`。

| 标志 | 值 | 作用 |
| --- | --- | --- |
| `--job` | `JOB_ID` | 取消该 Job 中的所有 Trial。与 `harbor hub job cancel JOB_ID` 相同。 |
| `--all` | — | 取消当前所有运行中的 Trial。 |
| `--reason` | `TEXT` | 记录取消原因。 |
| `--yes` | — | 跳过确认。 |

[`trial retry`](#retrying-a-hosted-trial) 中的筛选条件同样适用于此命令。

## 添加密钥 {#adding-secrets}

运行 `harbor hub secrets add NAME` 可将密钥上传到 Hub。

| 标志 | 值 | 作用 |
| --- | --- | --- |
| `--org` | `ORG_ID` | 保存密钥的组织。默认使用你的个人组织。 |
| `--job` | `JOB_ID` | 将密钥限定到单个 Job，而非整个账户。 |
| `--from-env` | — | 从同名的本地环境变量读取密钥值。 |
| `--yes`、`-y` | — | 无需提示即可替换现有密钥。 |

## 列出密钥 {#listing-secrets}

运行 `harbor hub secrets list` 可列出已上传密钥的名称和元数据。

| 标志 | 值 | 作用 |
| --- | --- | --- |
| `--org` | `ORG_ID` | 列出该组织中的密钥。 |
| `--job` | `JOB_ID` | 列出限定到该 Job 的密钥。 |
| `--include-revoked` | — | 包含已撤销的密钥。 |

## 删除密钥 {#deleting-secrets}
运行 `harbor hub secrets delete` 可撤销密钥。

| 标志 | 值 | 作用 |
| --- | --- | --- |
| `--org` | `ORG_ID` | 撤销该组织中的密钥。 |
| `--job` | `JOB_ID` | 撤销限定到该 Job 的密钥。 |
| `--purge` | — | 直接删除记录，使其不再出现在 `list --include-revoked` 中。 |

## 添加镜像注册表密钥 {#adding-an-image-registry-secret}
运行 `harbor hub secrets registry add` 可添加镜像注册表密钥。也支持 `secrets registry list` 和 `secrets registry delete`。

| 标志 | 值 | 作用 |
| --- | --- | --- |
| `--name` | `TEXT` | 用于之后选择凭据的显示名称。 |
| `--from-file` | `PATH` | 从文件读取凭据，例如 GAR 服务账户 JSON（结构化数据格式）。 |
| `--yes`、`-y` | — | 无需提示即可替换现有凭据。 |
