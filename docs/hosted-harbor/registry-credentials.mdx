title: 注册表凭据

`/registry-credentials` 用于保存拉取私有任务镜像所需的加密凭据，支持 Google Artifact Registry（GAR）、GitHub（代码托管平台） Container Registry（GHCR）和 Amazon Elastic Container Registry（ECR）。

以下示例使用 `$BASE` 和 `$KEY`。请从此处获取密钥：
[Harbor Hub（任务与结果共享平台） API（应用程序接口） key](/hosted-harbor/api-key).

```bash
export BASE=https://ofhuhcpkvzjlejydnvyd.supabase.co/functions/v1
export KEY=sk-harbor-...
```

## 保存凭据 {#storing-a-credential}

`POST /registry-credentials` 会验证并加密凭据，然后返回元数据，绝不会返回密钥本身。每个请求都必须提供 `registry_host` 和最多 100 个字符的 `display_name`，任务之后会通过这些信息选择凭据。系统会根据主机推断 provider，因此 `provider` 为可选项；如果提供该字段，必须与主机匹配。

| Provider | 主机 | 密钥字段 |
| --- | --- | --- |
| `gar` | `<region>-docker.pkg.dev` | `service_account_json` |
| `ghcr` | `ghcr.io` | `username`, `token` |
| `ecr` | `<account-id>.dkr.ecr.<region>.amazonaws.com` | `access_key_id`, `secret_access_key` |

GAR 凭据示例：

```json
{
  "registry_host": "us-east1-docker.pkg.dev",
  "display_name": "prod-puller",
  "service_account_json": "{...service account JSON...}"
}
```

请使用对目标仓库具有读取权限的服务账号，通常为作用域限定在该仓库的 `roles/artifactregistry.reader`。

GHCR 凭据示例：

```json
{
  "registry_host": "ghcr.io",
  "display_name": "github-packages-puller",
  "username": "octocat",
  "token": "ghp_..."
}
```

请使用权限限制为 `read:packages` 的经典 GitHub 个人访问令牌。

ECR 凭据示例：

```json
{
  "registry_host": "123456789012.dkr.ecr.us-east-1.amazonaws.com",
  "display_name": "production-ecr-puller",
  "access_key_id": "AKIAIOSFODNN7EXAMPLE",
  "secret_access_key": "..."
}
```

请使用长期有效的 IAM 访问密钥，并仅授予任务镜像拉取所需的 ECR 权限。以 `ASIA` 开头的临时会话凭据会被拒绝，因为它们还需要 Harbor（智能体评测框架） 不会保存的会话令牌。

成功响应示例如下：

```json
{
  "id": "00000000-0000-0000-0000-000000000003",
  "org_id": "00000000-0000-0000-0000-00000000000a",
  "provider": "gar",
  "registry_host": "us-east1-docker.pkg.dev",
  "display_name": "prod-puller",
  "fingerprint": "harbor-puller@my-project.iam.gserviceaccount.com",
  "status": "active",
  "created_at": "2026-08-13T14:30:00Z"
}
```

重复使用已有的 `display_name` 会返回 `409 replacement_required` 和现有记录的指纹；与普通密钥相同，请使用 `supersede_credential_id` 确认替换。每个组织最多可拥有 20 个有效注册表凭据。

对于 GAR，可以根据服务账号文件构造请求，避免 shell 引号转义问题：

```bash
curl -sS -X POST "$BASE/registry-credentials" \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d "$(jq -n --rawfile sa ./gar-puller.json \
    '{registry_host:"us-east1-docker.pkg.dev", display_name:"prod-puller", service_account_json:$sa}')"
```

## 列出和撤销注册表凭据 {#listing-and-revoking-registry-credentials}

`GET /registry-credentials` 会列出有效凭据，且只返回元数据。使用 `status=revoked` 或 `status=all` 可包含其他状态。

```bash
curl -sS "$BASE/registry-credentials?status=active" \
  -H "Authorization: Bearer $KEY"
```

`DELETE /registry-credentials` 默认会撤销凭据。只有需要永久删除已保存记录时，才将 `purge` 设为 `true`。

```bash
curl -sS -X DELETE "$BASE/registry-credentials" \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"credential_id":"00000000-0000-0000-0000-000000000003","purge":false}'
```

## 在任务中使用凭据 {#using-a-credential-in-a-job}

在与 `config` 同级的 `registry_credentials` 中，通过显示名称或 ID 固定使用某个已保存的凭据：

```json
{
  "config": {
    "job_name": "private-image-job",
    "agents": [
      {
        "name": "terminus-2",
        "model_name": "openai/gpt-4o",
        "secrets": [{"name": "OPENAI_API_KEY", "tag": "default", "as": "OPENAI_API_KEY"}]
      }
    ],
    "datasets": [
      {
        "name": "my-org/private-image-dataset",
        "ref": "latest"
      }
    ]
  },
  "registry_credentials": {
    "us-east1-docker.pkg.dev": "prod-puller"
  },
  "job_secrets": {
    "OPENAI_API_KEY": "sk-..."
  }
}
```

该映射表示：拉取 `us-east1-docker.pkg.dev` 上的镜像时，使用名为 `prod-puller` 的已保存凭据。键必须是受支持的注册表主机，最多可提供 20 项。

如果某个主机只有一个有效凭据，可以完全省略 `registry_credentials`。如果有多个匹配项，启动任务时必须通过显示名称、凭据 ID 或 Harbor 显示的带所有者信息的名称指定其中一个。
