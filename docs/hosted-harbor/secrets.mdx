title: 管理密钥
description: 通过 API（应用程序接口） 存储、列出、撤销和预检托管密钥
---

Harbor（智能体评测框架）的 `POST /secrets` 用于存储可重复使用的托管密钥，例如模型 API 密钥或 Task（任务）所需的环境变量。该接口与通过 Web UI（用户界面） [添加密钥](/hosted-harbor/web-ui#adding-secrets)的功能相同。

以下示例使用 `$BASE` 和 `$KEY`。请从[Harbor Hub（任务与结果共享平台） API 密钥](/hosted-harbor/api-key)获取密钥。

```bash
export BASE=https://ofhuhcpkvzjlejydnvyd.supabase.co/functions/v1
export KEY=sk-harbor-...
```

```json
{
  "scope": "user",
  "env_var": "OPENAI_API_KEY",
  "value": "sk-...",
  "provider": "openai"
}
```

`scope` 默认值为 `user`。如需将密钥限定在单个 Job（任务运行集合）中，请改用 `job`；此时必须提供 `job_id`。当 scope 为 `user` 时，不能提供 `job_id`。你可以传入 `org_id` 将密钥存入指定组织，也可以选择设置最多 64 个字符的 `provider` 标签。

响应只会返回元数据，不会返回密钥值：

```json
{
  "id": "00000000-0000-0000-0000-000000000002",
  "scope": "user",
  "job_id": null,
  "org_id": "00000000-0000-0000-0000-00000000000a",
  "env_var": "OPENAI_API_KEY",
  "provider": "openai",
  "value_last4": "abcd",
  "status": "active",
  "created_at": "2026-08-13T14:30:00Z"
}
```

## 替换密钥 {#replacing-a-secret}

如果 `env_var` 已有处于启用状态的密钥，存储同名密钥时不会静默覆盖。请求会返回 `409 replacement_required` 以及即将被替换的记录，以便你明确了解替换对象：

```json
{
  "error": {
    "code": "replacement_required",
    "message": "An active secret ending in abcd already exists. Confirm that you want to supersede it.",
    "existing": {
      "id": "00000000-0000-0000-0000-000000000002",
      "scope": "user",
      "env_var": "OPENAI_API_KEY",
      "value_last4": "abcd",
      "created_at": "2026-08-13T14:30:00Z"
    }
  }
}
```

再次发送相同请求，并附上 `"supersede_credential_id": "<existing.id>"` 以确认。如果期间发生变化，导致该 ID 不再对应当前启用的密钥，请求会返回 `409 replacement_stale`；此时应重新读取记录后再重试。替换密钥需要组织所有者权限。

下文介绍的 Registry 密钥也遵循相同规则。

## 列出和撤销密钥 {#listing-and-revoking-secrets}

`GET /secrets` 只会以元数据形式列出你的密钥。可以使用 `scope`、`job_id` 和 `status` 筛选；`status` 可设为 `active`（默认值）、`revoked` 或 `all`。

```bash
curl -sS "$BASE/secrets?scope=user&status=active" \
  -H "Authorization: Bearer $KEY"
```

```json
{
  "secrets": [
    {
      "id": "...",
      "scope": "user",
      "job_id": null,
      "env_var": "OPENAI_API_KEY",
      "provider": "openai",
      "value_last4": "abcd",
      "status": "active",
      "created_at": "...",
      "last_used_at": null
    }
  ]
}
```

`DELETE /secrets` 根据环境变量名称撤销密钥。仅当要永久删除存储记录而不是将其标记为已撤销时，才将 `purge` 设为 `true`。

```json
{
  "scope": "user",
  "env_var": "OPENAI_API_KEY",
  "purge": false
}
```

## 启动前检查密钥 {#checking-secrets-before-launching}

`POST /secrets/preflight` 会执行提示性检查，报告配置中的每个 Agent（智能体）是否会实际获得可供其模型验证身份的凭据。此检查本身不会阻止启动。

```json
{
  "config": {
    "agents": [
      {
        "name": "terminus-2",
        "model_name": "openai/gpt-5-mini",
        "secrets": [{"name": "OPENAI_API_KEY", "tag": "default", "as": "OPENAI_API_KEY"}]
      }
    ]
  },
  "organization": "my-org",
  "declared_env_vars": ["OPENAI_API_KEY"]
}
```

由于密钥按 Agent 分别限定范围，检查会针对每个 Agent 自己选择的密钥执行，而不是检查组织存储的所有密钥：只有当 Agent 的 `secrets` 列出某个名称**并且**该名称能够解析时，才会将其计为有效。它必须对应所属组织中的启用密钥，或是 `declared_env_vars` 中的名称。对于计划作为 `job_secrets` 传入的一次性密钥，请发送 `declared_env_vars`；预检无法读取这些密钥的值。

响应会报告总体状态 `ok`、`providers` 中各提供方的结果、`agent_requirements` 中各 Agent 的详细信息（包括 `model`、`provider`、`missing_env_vars` 和 `configured`），以及 `task_requirements` 中解析后 Task 硬性要求的环境变量。为兼容现有客户端，响应仍会返回旧的 `agents` 字段。只有密钥已配置**且**可供任务提供（`supplyable`）时，才算满足 Task 的环境变量要求。保留给基础设施使用的名称（如 `PATH`、`LD_PRELOAD`，以及以 `MODAL_`、`SUPABASE_`、`HOSTED_HARBOR_` 或 `GCP_` 开头、或以 `_PROXY` 结尾的名称）绝不会导出到 Trial（单次运行）的环境中，因此即使你提供自己的密钥，也无法满足要求这些变量的 Task。
