Harbor 会在隔离环境中运行每个 Trial（单次运行）。本地运行时适合
开发；远程提供方可以释放本地资源并支持更高的并发数。
concurrency.

<Note>
  Harbor 在 CLI（命令行界面）（`--env`/`-e`）和 Job（任务运行集合） 配置（`environment.type`）中将 Sandbox（沙箱）
  称为“**环境**”。我们知道这个名称不理想，但现在已经太迟，无法更改。
</Note>

## 使用云 Sandbox {#run-with-a-cloud-sandbox}

默认情况下不会安装 Sandbox。请安装一种 Sandbox，例如
[Daytona（云沙箱平台）](https://www.daytona.io/)（云端开发沙箱）：

```bash
uv tool install "harbor[daytona]"
```

将 `daytona` 替换为[所有 Sandbox 选项](#available-sandboxes)中的名称，即可安装
对应 Sandbox。若要安装**所有**预集成 Sandbox，请运行：

```bash
uv tool install "harbor[cloud]"
```

本地运行时（例如 `docker`（容器平台））不需要 Harbor 的可选 Python（编程语言） 依赖，但
仍必须安装对应的运行时或 CLI。

<Tabs>
  <Tab title="命令行">
    ```bash
    export DAYTONA_API_KEY="..."
    harbor run \
      -d terminal-bench@2.0 \
      -a codex -m openai/gpt-5.6-sol \
      -e daytona \
      -n 32
    ```
  </Tab>

  <Tab title="配置文件">
    ```json config.json
    {
      "n_concurrent_trials": 32,
      "environment": {
        "type": "daytona"
      },
      "agents": [
        {
          "name": "codex",
          "model_name": "openai/gpt-5.6-sol"
        }
      ],
      "datasets": [
        {
          "name": "terminal-bench",
          "version": "2.0"
        }
      ]
    }
    ```

    ```bash
    export DAYTONA_API_KEY="..."
    harbor run --config config.json
    ```
  </Tab>
</Tabs>

<Accordion title="其他方式：从源码运行 Harbor">
  从源码运行 Harbor 时，`--extra daytona` 会在运行命令前安装 Daytona 的
  可选依赖：

  ```bash
  export DAYTONA_API_KEY="..."
  uv run --no-dev --extra daytona harbor run \
    -t hello-world/hello-world \
    -a codex -m openai/gpt-5.6-sol \
    -e daytona
  ```
</Accordion>

如果提供方支持，Harbor 会执行预检。否则会在提供方启动时
报告缺少的设置。**注意：**请参阅[环境变量](/jobs/environment-variables)，
配置提供方凭据并控制哪些变量会进入 Sandbox。

## 常见 Sandbox CLI 选项 {#common-sandbox-cli-options}

| 标志 | 用途 | 默认值 |
| --- | --- | --- |
| `-e`、`--env` | 选择内置 Sandbox 或自定义导入路径。 | `docker` |
| `--ek`、`--environment-kwarg` | 传递提供方专用的构造函数选项。可重复指定。 | 无 |
| `-n`、`--n-concurrent` | 限制并发 Trial 数量。 | `4` |
| `--force-build`、`--no-force-build` | 重新构建或复用 Task（任务） 环境。 | `--no-force-build` |
| `--delete`、`--no-delete` | 在 Trial 结束后删除或保留 Sandbox。 | `--delete` |
| `--cpus`、`--memory` | 选择 `auto`、`limit`、`request`、`guarantee` 或 `ignore`。 | `auto` |
| `--override-cpus`、`--override-memory-mb`、`--override-storage-mb`、`--override-gpus`、`--override-tpu` | 覆盖本次运行的 Task 资源。 | Task 配置 |
| `--env-file` | 加载宿主机凭据和其他环境变量。请参阅[环境变量](/jobs/environment-variables)。 | 无 |

提供方的生命周期规则可能覆盖 `--no-delete`。运行 `harbor run --help` 查看
所有环境选项；每个提供方还会定义自己的
`--environment-kwarg` 值。

## 提供方能力 {#provider-capabilities}

Sandbox 能力因提供方而异，也可能取决于 Task 模式或提供方设置。
settings.

<Accordion title="Task 和硬件能力">
  | 能力 | 支持的环境 |
  | --- | --- |
  | Docker Compose（多容器编排工具） | `docker`、`podman`、`daytona`、`modal`、`ec2`、`gke`、`islo`、`langsmith`、`novita`、`blaxel`、`beam`、`hyperbrowser`、`vercel`、`runta`、`prime`、`sail`、`sbx`、`tensorlake`、`boxd`、`superserve` |
  | GPU（图形处理器） | `daytona`、`modal`、`gke`、`beam`、`opensandbox`、`prime`、`docker` |
  | TPU（张量处理器） | `gke` |
  | Windows（微软操作系统） | `docker`、`daytona`、`cua-cloud`、`use-computer` |
  | 宿主机挂载日志 | `docker`、`podman`、`apple-container`、`singularity` |
  | 通过 SSH（安全远程连接协议） 实时传输 | `daytona`、`docker`、`modal`、`tensorlake` |

  Modal（云计算与沙箱平台） 的 GPU 支持取决于其运行时设置。GKE（Google 托管 Kubernetes 服务） 仅在单容器 Task 中提供 GPU 和 TPU。
  Prime（云计算提供商） GPU 也仅支持单容器 Task。
  `cua-cloud` 和 `use-computer` 需要启用各自的
  Windows 平台设置。
</Accordion>

<Accordion title="网络能力">
  | 能力 | 支持的环境 |
  | --- | --- |
  | Disable internet | `docker`, `podman`, `daytona`, `e2b`, `modal`, `runloop`, `langsmith`, `ec2`, `gke`, `novita`, `islo`, `tensorlake`, `cwsandbox`, `blaxel`, `opensandbox`, `beam`, `skypilot`, `hyperbrowser`, `vercel`, `runta`, `prime`, `mosaic`, `smol`, `sail`, `sbx`, `boxd`, `superserve` |

  | Wildcard hostnames | `docker`, `podman`, `daytona`, `e2b`, `modal`, `runloop`, `langsmith`, `novita`, `blaxel`, `hyperbrowser`, `vercel`, `runta`, `prime`, `sail`, `superserve` |
  | IPv4 addresses | `docker`, `podman`, `daytona`, `e2b`, `modal`, `novita`, `tensorlake`, `beam`, `hyperbrowser`, `prime`, `mosaic`, `smol`, `sail`, `superserve` |
  | IPv6 addresses | `docker`, `podman`, `beam`, `smol` |
  | IPv4 CIDRs | `docker`, `podman`, `daytona`, `modal`, `novita`, `tensorlake`, `beam`, `hyperbrowser`, `prime`, `mosaic`, `smol`, `sail`, `superserve` |
  | IPv6 CIDRs | `docker`, `podman`, `beam`, `smol` |
  | 运行时策略变更 | `docker`, `podman`, `daytona`, `e2b`, `modal`, `novita`, `islo`, `beam`, `hyperbrowser`, `vercel`, `runta`, `prime`, `sail`, `sbx`, `superserve` |

  Docker 和 Podman（容器管理工具） 需要 Harbor 的出站流量控制支持。Daytona、
  Novita（沙箱提供商）、Blaxel 和 Vercel 的允许列表仅适用于单容器 Task。GKE 只能在
  Compose 模式下禁用互联网。Islo 的运行时策略变更要求使用其
  默认网关配置。
  Modal（云计算与沙箱平台）支持单容器和 Compose Task 的允许列表及运行时策略变更。
  仅使用 CPU（中央处理器） 的 Compose Task 默认运行于 VM（虚拟机）；GPU Task 保留 gVisor（隔离容器运行时）。
  使用 `--ek modal_vm_runtime=false` 可选择退出。
  请参阅[网络策略](/tasks/network-policies#modal-compose)。
  `sbx` 在 `target=local` 时不支持主机名允许列表或运行时策略变更。


  SBX 镜像构建会遵循 Task 的网络限制，因此必须允许
  所需下载主机。
</Accordion>
