本教程将创建一个小型 Task，并使用 Rewardkit（奖励验证工具库）进行评分。Agent（智能体）会编写文本统计模块和分析脚本。Verifier（验证器）分别评估 `structure` 和 `correctness`，并将二者汇总为主奖励 `reward`。最终 Task 位于 Harbor（智能体评测框架）仓库的 [reward-kit-example](https://github.com/harbor-framework/harbor/tree/main/examples/tasks/reward-kit-example)。

## 步骤 1：创建 Task {#step-1%3A-create-the-task}

[安装 Harbor](/getting-started/installation)，然后创建 Task 目录：

```bash
harbor task init textstats
```

生成的 Task 结构如下：

```bash
textstats/
├── instruction.md
├── task.toml
├── environment/
│   ├── Dockerfile
│   └── sample.txt
├── solution/
│   └── solve.sh
└── tests/
    ├── test.sh
    ├── criteria.py            # shared custom criteria
    ├── reward.toml            # main reward across dimensions
    ├── structure/
    │   ├── files_exist.py
    │   ├── functions_defined.py
    │   └── reward.toml
    └── correctness/
        ├── word_count.py
        ├── most_common.py
        ├── reward.toml
        └── pipeline/
            └── pipeline_runs.py
```

## 步骤 2：编写指令和环境 {#step-2%3A-write-the-instruction-and-environment}

````markdown title="textstats/instruction.md"
Create a text statistics module and analysis script.

1. `/app/textstats.py` with `word_count(text: str) -> int` (words split by
   whitespace) and `most_common(text: str) -> str` (most frequent word,
   lowercase, empty string for empty input).
2. `/app/analyze.py`, which reads `/app/sample.txt` and writes
   `/app/results.json` as:

```json
{ "word_count": <int>, "most_common": "<string>" }
```
````

环境需要 Python（编程语言）、`uv` 和示例文本：

```dockerfile title="textstats/environment/Dockerfile"
FROM ubuntu:24.04

COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/

WORKDIR /app

COPY sample.txt /app/sample.txt
```

```text title="textstats/environment/sample.txt"
the quick brown fox jumps over the lazy dog
the dog barked at the fox
the fox ran away quickly
```

保留生成的 `task.toml`，无需更改。

## 步骤 3：编写解决方案 {#step-3%3A-write-the-solution}

Oracle Agent 会运行此脚本，确认 Task 可解：

```bash title="textstats/solution/solve.sh"
#!/bin/bash

cat > /app/textstats.py << 'EOF'
from collections import Counter


def word_count(text: str) -> int:
    return len(text.split())


def most_common(text: str) -> str:
    words = text.lower().split()
    return Counter(words).most_common(1)[0][0] if words else ""
EOF

cat > /app/analyze.py << 'EOF'
import json
from pathlib import Path

from textstats import most_common, word_count

text = Path("sample.txt").read_text().strip()
results = {"word_count": word_count(text), "most_common": most_common(text)}
Path("results.json").write_text(json.dumps(results, indent=2))
EOF

cd /app && uv run python analyze.py
```

## 步骤 4：从测试脚本运行 Rewardkit {#step-4%3A-run-rewardkit-from-the-test-script}

Harbor 会将 `tests/` 复制到 `/tests` 并运行 `test.sh`。该脚本只调用 Rewardkit；Rewardkit 会查找 `/tests` 下的所有判定标准，针对 `/app` 运行，并将结果写入 `/logs/verifier/reward.json`：

```bash title="textstats/tests/test.sh"
#!/bin/bash
uvx --python '>=3.12,<3.14' --from 'harbor-rewardkit==0.2.*' rewardkit /tests
```

## 步骤 5：添加结构判定标准 {#step-5%3A-add-structure-criteria}

`tests/` 的每个子目录都会生成一个以目录命名的奖励，其中每个 Python 文件都会生成一个以文件名命名的分数。`structure` 用于检查必需文件和函数是否存在，使用的是[内置判定标准](/rewardkit/built-in-criteria)。路径相对于 `/app`：

```python title="textstats/tests/structure/files_exist.py"
from rewardkit import criteria

criteria.file_exists("textstats.py")
criteria.file_exists("analyze.py")
criteria.file_exists("results.json")
```

```python title="textstats/tests/structure/functions_defined.py"
from rewardkit import criteria

criteria.file_contains("textstats.py", "def word_count")
criteria.file_contains("textstats.py", "def most_common")
```

## 步骤 6：添加正确性判定标准 {#step-6%3A-add-correctness-criteria}

检查返回值需要自定义逻辑。在 tests 根目录定义一次，并设置 `shared=True`，这样各个维度都能调用。返回 `float` 可提供部分分数：

```python title="textstats/tests/criteria.py"
import importlib.util
from pathlib import Path

from rewardkit import criterion


def _load_module(workspace: Path, name: str):
    spec = importlib.util.spec_from_file_location(name, workspace / f"{name}.py")
    mod = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(mod)
    return mod


@criterion(shared=True)
def word_count_correct(workspace: Path) -> float:
    try:
        mod = _load_module(workspace, "textstats")
    except Exception:
        return 0.0
    cases = [("hello world", 2), ("one", 1), ("", 0), ("the quick brown fox", 4)]
    return sum(mod.word_count(t) == n for t, n in cases) / len(cases)


@criterion(shared=True)
def most_common_correct(workspace: Path) -> float:
    try:
        mod = _load_module(workspace, "textstats")
    except Exception:
        return 0.0
    cases = [("the cat and the dog", "the"), ("hello hello world", "hello"), ("", "")]
    return sum(mod.most_common(t) == w for t, w in cases) / len(cases)
```

在 `correctness` 中每个文件调用一项共享判定标准；将端到端流程检查放入嵌套的 `pipeline/` 组，以便单独设置权重：

```python title="textstats/tests/correctness/word_count.py"
from rewardkit import criteria

criteria.word_count_correct()
```

```python title="textstats/tests/correctness/most_common.py"
from rewardkit import criteria

criteria.most_common_correct()
```

```python title="textstats/tests/correctness/pipeline/pipeline_runs.py"
from rewardkit import criteria

criteria.command_succeeds("python analyze.py")
criteria.json_key_equals("results.json", "most_common", "the")
```

## 步骤 7：配置评分 {#step-7%3A-configure-the-scoring}

默认情况下，Python 文件中的判定标准按权重取平均值，同一维度下的文件权重相等，各维度分数分别写入 `reward.json`。可通过三个 `reward.toml` 文件调整这些规则。

只有所有文件和函数都存在时，`structure` 才会通过。`[scoring.<stem>]` 用于配置单个 Python 文件中的判定标准，未命名的 `[[reward]]` 用于组合这些文件：

```toml title="textstats/tests/structure/reward.toml"
[scoring.files_exist]
aggregation = "all-pass"

[scoring.functions_defined]
aggregation = "all-pass"

[[reward]]
aggregation = "all-pass"
```

在 `correctness` 中，两个函数检查和嵌套 `pipeline` 组按名称设置权重：

```toml title="textstats/tests/correctness/reward.toml"
[[reward]]
weights = { word_count = 3.0, most_common = 2.0, pipeline = 1.0 }
```

根目录的 `reward.toml` 会添加 Harbor 读取的主 `reward`。仅当两个维度的分数都为 `1.0` 时，主奖励才为 `1.0`：

```toml title="textstats/tests/reward.toml"
[[reward]]
name = "reward"
aggregation = "all-pass"
```

Verifier 现在会写入：

```json title="/logs/verifier/reward.json"
{ "correctness": 1.0, "structure": 1.0, "reward": 1.0 }
```

有关汇总模式，请参阅[分数组合方式](/rewardkit/quick-start#how-scores-are-combined)。

## 步骤 8（可选）：添加 LLM 裁判 {#step-8-optional-%3A-add-an-llm-judge}

添加 `quality` 维度，在裁判 TOML（配置文件格式） 中定义评分，并通过 `task.toml` 传入 API（应用程序接口） 密钥：

```toml title="textstats/tests/quality/quality.toml"
[judge]
judge = "anthropic/claude-sonnet-5"
files = ["/app/textstats.py", "/app/analyze.py"]

[[criterion]]
description = "Are the functions implemented in a clear and idiomatic way?"
type = "binary"
```

```toml title="textstats/task.toml"
[verifier.env]
ANTHROPIC_API_KEY = "${ANTHROPIC_API_KEY}"
```

`quality` 会成为第四个分数，并纳入根级 `all-pass` 汇总。这里使用二元判定，因为 `all-pass` 要求分数为 `1.0`，Likert 裁判很少会给出满分。有关 Agent 裁判和完整 TOML 参考，请参阅[裁判判定](/rewardkit/judge-criteria)。

## 步骤 9：运行并检查 {#step-9%3A-run-and-inspect}

使用 Verifier 运行解决方案，然后打开查看器：

```bash
harbor run -p textstats -a oracle
harbor view ./jobs
```

每个维度都应得分为 1。在 Trial（单次运行） 的 **Verifier Logs** 标签页中，**Rewards** 部分会将 `reward-details.json` 显示为树状结构，其中包含每项判定的分数、权重和错误信息。
