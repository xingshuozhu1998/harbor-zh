---
title: "产物收集"
description: "保留 Trial（单次运行） 期间生成的文件。"
---

Harbor（智能体评测框架） 会在智能体阶段结束后收集产物，用于本地查看文件，以及将智能体生成的文件传输到独立验证器沙箱。

## 自动收集产物 {#automatic-artifact-collection}

<Warning>
  即将移除对 `/logs/artifacts/` 的自动收集。新任务请显式配置产物。
</Warning>

主沙箱中写入 `/logs/artifacts/` 的文件会被**自动**收集。Harbor 不会指示智能体使用该目录；如果需要智能体生成产物，请在任务指令中指定此目录。

```md instruction.md
Save the final report to `/logs/artifacts/report.json`.
```

这些文件会保存在 `<trial-dir>/artifacts/logs/artifacts/` 下，并显示在查看器的[**产物**标签页](/results/view-job-results#trial-files)中。

## 配置产物收集 {#configure-artifact-collection}

可以通过运行参数 `--artifact`、`config.json` 中的 `artifacts`，或任务 `task.toml` 中的 `artifacts` 来配置。

<Note>以下两种形式都接受文件或目录，也可以指定多个产物。</Note>

### 基本用法 {#basic}

<Tabs>
  <Tab title="CLI">
    `--artifact` 可以重复指定。

    ```bash
    export OPENAI_API_KEY="..."
    harbor run \
      -t hello-world/hello-world \
      -a codex -m openai/gpt-5.6-sol \
      --artifact /app/hello.txt
    ```
  </Tab>

  <Tab title="Run config">
    ```json config.json
    {
      "artifacts": ["/app/hello.txt"]
    }
    ```
  </Tab>

  <Tab title="Task config">
    ```toml task.toml
    artifacts = ["/app/hello.txt"]
    ```
  </Tab>
</Tabs>

`/app/hello.txt` 会在主机上保存为 `<trial-dir>/artifacts/app/hello.txt`。

运行级产物会与任务级产物合并。

### 高级选项 {#advanced-options}

使用对象形式可更改保存路径，或排除目录中的文件。这些选项需要通过运行配置或任务配置设置。添加多个条目即可同时收集文件和目录。

<Tabs>
  <Tab title="Run config">
    ```json config.json
    {
      "artifacts": [
        {
          "source": "/workspace/output",
          "destination": "output",
          "exclude": ["*.tmp"]
        },
        {
          "source": "/app/report.json",
          "destination": "report.json"
        }
      ]
    }
    ```
  </Tab>

  <Tab title="Task config">
    ```toml task.toml
    artifacts = [
      { source = "/workspace/output", destination = "output", exclude = ["*.tmp"] },
      { source = "/app/report.json", destination = "report.json" },
    ]
    ```
  </Tab>
</Tabs>

在主机上，这些内容分别保存为 `<trial-dir>/artifacts/output/` 和 `<trial-dir>/artifacts/report.json`。

| 字段 | 说明 |
| --- | --- |
| `source` | 沙箱中的文件或目录。 |
| `destination` | `<trial-dir>/artifacts/` 下的可选相对路径。 |
| `exclude` | 收集目录时要排除的匹配模式。 |
| `service` | 要从中收集文件的 Compose 服务。默认为 `main`。 |

## 独立验证器 {#separate-verifier}

验证器会在新的沙箱中运行。Harbor 只会从智能体沙箱传输已声明的产物和自动收集的 `/logs/artifacts/` 目录。使用相同的 `artifacts` 字段，无需单独配置验证器产物。

```toml task.toml
artifacts = ["/app/report.json"]

[verifier]
environment_mode = "separate"
```

Harbor 会从智能体沙箱收集 `/app/report.json`，并将其放入验证器沙箱中的 `/app/report.json`。`destination` 只控制产物在主机上的保存位置。

了解更多信息，请参见[独立验证器](/tasks/separate-verifier)。

<Warning>
  独立验证器不会继承运行时挂载或 `extra_docker_compose` 覆盖配置。请在验证器镜像中安装评分依赖，并将智能体输出作为产物传输。
</Warning>

## 收集清单 {#collection-manifest}

Harbor 会将 `<trial-dir>/artifacts/manifest.json` 作为收集报告写入。每个条目记录产物的来源、主机目标位置、服务、文件类型和状态：`ok`、`empty`、`failed` 或 `skipped`。

目录条目还会记录收集时使用的 `exclude` 模式；重新评分时，更新后的声明必须继续使用相同模式。

<Frame caption="manifest.json">
  <img
    src="/images/artifact-viewer-manifest.png"
    alt="Harbor 查看器显示 manifest.json，其中包含产物来源、目标位置、类型和状态"

</Frame>

<Note>
  收集失败会记录在清单中，但不会导致 Trial 失败。
</Note>

如果两个条目会写入重叠的主机路径，Harbor 会保留第一个条目，并将另一个记为 `skipped`，避免覆盖文件。

## Sidecar 产物 {#sidecar-artifacts}

对于[多容器任务](/tasks/multi-container)，请将 `service` 设为 Compose 服务。`verifier.collect` 钩子可以先将运行时状态写入文件，再进行收集。

```toml task.toml
artifacts = [
  { source = "/var/log/api/orders.log", service = "api" },
  { source = "/tmp/stats.json", service = "api" },
]

[[verifier.collect]]
service = "api"
command = "curl -s http://localhost:8000/stats > /tmp/stats.json"
timeout_sec = 30
```

Sidecar 产物和收集钩子需要支持 Compose 的沙箱。请参见[可运行示例](https://github.com/harbor-framework/harbor/tree/main/examples/tasks/sidecar-artifacts)
and [provider capabilities](/sandboxes/pre-integrated-sandboxes#provider-capabilities).

## 多步骤任务 {#multi-step-tasks}

对于[多步骤任务](/tasks/multi-step)，步骤级产物会与任务级和运行级产物合并。Harbor 会在每个步骤的验证器运行前收集这些产物，并保存在 `steps/<step-name>/artifacts/` 下。
